# Wanning 性能基准与基线(W-30)

零依赖手写基准(`crates/wanning-bench`,不引 criterion),所有数字由真实运行跑出,
本文只是记录。**口径全部钉死在 `crates/wanning-bench/src/lib.rs` 的常量里**,测试
`tests/bench.rs` 锁定这些常量不被悄悄改动。

## 复现步骤

```bash
# 依赖:Rust(本仓基线 rustc 1.96.0);零额外依赖
CARGO_HOME=<你的 cargo 目录> cargo run -p wanning-bench --release
```

输出:五项基准 × 每项 5 轮实测(另含 1 轮预热,不计入)+ 中位数。

| 项 | 值 |
| --- | --- |

笔记本 CPU,散热状态会影响数字;同机重跑偏差见下文「复跑一致性」。

## 五项基准口径

| 标识 | 测什么 | 单位 | 默认规模 |
| --- | --- | --- | --- |
| `gate_decide_allow` | 闸六道门全走 + 预算扣减(金额 100..499 分,nonce 单调) | 判定/s | 200_000 笔/轮 |
| `gate_decide_deny_over_budget` | 拒绝路径 steady state(金额恒为上限+1,预算门拒;拒绝不耗号) | 判定/s | 200_000 笔/轮 |
| `wal_append` | WAL 追加(序列化 + 完整性链 + 写盘 + flush) | 行/s | 20_000 行/轮 |
| `wal_replay` | 同一份账本回放(逐行验链 + 状态重建 + 回放对账,**全计入**——「重启一次要多久」的真实口径) | 行/s | 50_000 行 |
| `audit_html_export_5k` | W-22 审计回放页导出(验链→对账→渲染→原子落盘,全计入) | ms/次 | 5_000 行账 |

造数:xorshift64* 固定种子(与 W-04 property 测试同族),金额可变但可复现。
回放/导出用的账本由 `WanningState` 真实写路径生成(1 行注册 + N 行放行),
不是手拼 JSON。

### 中位数对比

| 基准 | 第 1 次 | 第 2 次 | 偏差 |
| --- | --- | --- | --- |
| gate_decide_allow | 1_229_638 判定/s | 1_292_843 判定/s | ~5% |
| gate_decide_deny_over_budget | 7_601_499 判定/s | 7_994_435 判定/s | ~5% |
| wal_append | 333_035 行/s | 381_231 行/s | ~14% |
| wal_replay | 424_144 行/s | 423_959 行/s | <0.1% |
| audit_html_export_5k | 39.5 ms | 41.8 ms | ~6% |

两轮全部同数量级;最大偏差 ~14%(wal_append,磁盘写入吞吐受系统状态影响),
回放(纯 CPU 读)几乎不漂。**结论口径:判定 ~1.2M/s(Allow)/ ~7.6M/s(Deny),
WAL 追加 ~0.33M 行/s,回放 ~0.42M 行/s,5k 行审计页 ~40ms。**

### 怎么读这些数

- 判定是内存操作,百万级/秒——闸不是性能瓶颈,瓶颈永远在渠道侧网络与人工审批。
- WAL 追加带 flush(每行落盘),数量级掉到 ~1/4,这是审计持久性的成本;
  回放(含逐行验链 + 回放对账)50k 行 < 0.2 s——「诚实账本」的验证成本可接受。
- 审计页 5k 行 ~40ms,对谈合作用的 protocol receipt 生成是即时的。

## 如何对比回归

同机同口径跑 `cargo run -p wanning-bench --release`,与本文基线比**中位数**;
数量级掉档(如判定从 ~1.2M 掉到 ~100k)才算回归,±20% 以内当噪声
(见上表 wal_append 的 ~14% 自然偏差)。

## 边界(诚实记录)

- 本机数字只代表本机:笔记本 CPU/Windows/NTFS,换机器必须重跑,不横向套用。
- 测试(`tests/bench.rs`)只用小参数锁「可运行、口径正确、数值合法」,
  绝不把测试里的小跑数字当基准写档。
- 基准委托的预算上限 1 亿元,保证 Allow 口径永不触顶;这不是业务上限,
  只是基准的量程设定。
