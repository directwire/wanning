# Wanning 合规红线(执行会话必读,无豁免权)

> 依据:《非银行支付机构监督管理条例》(2024-05-01 施行)框架层分析。
> 落地为产品形态前须过执业律师复核;本清单是监管明文层面的硬约束,先于一切功能。

## 铁律(违反即停工上报老板)

1. **禁止资金沉淀/归集/转付**——每笔钱必须用户(老板本人)支付账户直付商户。
   出现"先进我们账户/我们的中间层再出"的结构 = 无证支付业务(二清)= 刑事红线,
   立即停工上报,不得"先跑通再说"。
2. **只用老板本人账户 + 小额真实消费**;不给任何第三方代理支付。
3. **必须走官方开放平台 API**;禁止模拟点击/爬虫下单(风控封号 + ToS + 证据效力三重原因)。
4. **不碰数字人民币程序化接入**(个人拿不到受理资质,2026-09-02 已论证);
   **不碰虚拟货币结算**(境内全面禁止)。
5. **密钥/商户凭据一律仓库外 env 文件**(同 mainnet-deploy.env 惯例),永不进 git、
   不落命令行、不进日志。
6. **对外输出只谈架构分层**(授权/账本/结算/受理四层,受理留给持牌机构),
   不披露资金通道细节、账号信息、密钥材料。

## 合法性依据(为什么"闸"是干净的)

- Wanning 是**意图层软件**:预算/撤销/重放/审计。不触碰资金流,不参与结算。
- 资金路径:用户实名支付工具(免密协议与平台签)→ 商户,全程无我们位置。
- 对应合法形态:"授权额度 + 自动扣款"(支付宝小额免密先例,存在十余年)。
- 红旗信号自查:资金先进受托方再转出?为多用户归集?代收代付赚差?
  以"支付"名义对外服务?——任何一条命中即越线。
